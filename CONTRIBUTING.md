# Contributing to MAXY

## Working agreements
- Keep modules small and focused.
- Prefer typed interfaces and explicit dependencies.
- Do not call a feature working until tests or reproducible manual verification exist.
- Do not introduce hidden cloud inference or telemetry.
- Never bypass the permission gate.

## Commit style
Use concise messages, for example:
- `chore: establish project structure`
- `feat: add Ollama chat provider`
- `test: cover action approval policy`

## Before a pull request
- Run tests and Ruff.
- Update documentation and the roadmap.
- Explain new permissions, network access, or data collection.
